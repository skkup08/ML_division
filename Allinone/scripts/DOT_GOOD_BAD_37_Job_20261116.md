## 실행 절차
1. Google Drive 연결과 Colab 사용 가능 여부를 실제 확인한다. 필요한 최초 로그인이나 권한 승인만 사용자에게 요청하라. 사용자에게 코드를 복사/실행하게 떠넘기지 말고 접근 가능한 컴퓨터/브라우저/코딩 환경에서 직접 실행하라.
2. 위 37종의 `GOOD/BAD` 라벨 영상·이미지 개수, 원본 영상 ID 또는 촬영자/피험자 ID, 카메라 방향, 라이선스, 중복 여부를 `coverage_37.csv`로 정리한다. 기구 인식/운동 인식/자세 분류/원클래스 상태를 서로 구분하라.
3. 기존 Drive에서 학습 가능한 데이터를 먼저 사용한다. QEVD, 공개 시범 영상, AI-Hub 및 신규 외부 자료를 검토할 때 원본의 사용 허가·수집 범위를 확인한다. AI-Hub 약관상 별도 허가 없는 국외 반출이 문제 될 수 있으므로 승인 없이 Colab/Drive에 업로드하지 마라. 제한된 원본 데이터를 공유 또는 재배포하지 마라. 공개 시범 영상은 검증된 GOOD/BAD 라벨이 없으면 GOOD/BAD 분류의 정답 자료로 꾸미지 마라.
4. GOOD/BAD **두 클래스의 명시적이고 믿을 수 있는 라벨**과 충분히 독립적인 사람/촬영 세션 데이터가 있는 종목은 동작별 이진 분류기를 학습한다. 사람이 적으면 독립 검증 부족을 명시한다. GOOD만 있는 종목은 원클래스 이상탐지로 구분해 별도 저장하며 GOOD/BAD 이진 분류를 달성한 것으로 표시하지 마라. 변형 동작을 일반 운동 모델로 자동 대체할 때에는 의미가 달라지므로 별도 근거 없이 연결하지 마라.
5. MediaPipe 관절 특징 추출부터 영상 전처리·예측까지 학습/추론 규격을 일치시키고, 각 운동에 대해 피험자 단위(가능할 때) train/validation/test 분리, label 누출·동일 원본/프레임 중복 제거, 혼동행렬, BAD recall, GOOD recall, balanced accuracy를 저장하라. 모델 성능이 나쁘거나 데이터가 부족하면 실패/제한사항을 정확히 보고하라. 단순히 90% 달성만을 위해 테스트를 재사용하거나 과적합시키지 마라.
6. 새로 학습된 모델은 `Allinone/GOOD_BAD_37_Dot/<run_id>/`에 저장하라. `models/`, `coverage_37.csv`, `metrics.csv`, `training_manifest.csv`, `errors.csv`, `README_KO.md`, `prediction_examples/`을 남겨라. 기존 파일을 삭제·덮어쓰지 마라.
7. 새 모델을 AI GYM COACH 웹앱과 연동할 수 있도록 운동명/모델/입력 형태/추론 특징/피드백 범위가 표시된 `registry.json`을 생성하라. 실시간 영상에서는 연속 관절 추적/짧은 슬라이딩 윈도우/경고의 안정적 지속시간 제한을 적용하라. 영상 전체를 입력받는 모델을 매 프레임에 그대로 적용했다고 주장하지 마라. 구체적 오류 위치 라벨이 없는 GOOD/BAD 모델은 '자세 재확인 필요' 등의 일반 안내만 표시해라.
8. 테스트가 끝나면 **원래 37종 중 이진 GOOD/BAD 가능/원클래스만 가능/데이터 부족/동작 매핑 확인 필요** 각각의 수를 합계가 37이 되도록 보고하라. 실제 작업된 Colab 노트북 링크, 최종 Drive 저장 폴더 링크, 검증 결과, 다음 앱 연동 우선순위를 알려라.
